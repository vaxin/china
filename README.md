# 古城沙盘 · 可运行原型

这是一个浏览器优先的 3D 中国古代城市沙盘原型。当前二十四条垂直切片已经贯通：

- Babylon.js WebGL2 3D 沙盘与正交相机
- 32×32 tile picking、合法/非法建造预览
- Dedicated Web Worker 权威建造规则
- 重叠、越界和快速双击保护
- IndexedDB 自动存档、刷新恢复与损坏存档隔离
- 1×1 道路铺设、城门入口与正交道路连通
- Worker 确定性 tick、道路服务和每户 5 人入住
- 道路、住宅和水井拆除，以及断路迁出、补路自愈
- 住宅先落宅基地，流民从城门沿道路抵达并依次完成地基、木架、封顶和成屋
- 施工阶段、流民位置与动作进入权威模拟、自动存档和刷新恢复
- 入住后每户保留一名持久市民代表，按真实劳力岗位逐格通勤、工作、返家或在住宅周边活动；断路返家、补路恢复，身份和阶段随存档保存
- 农夫、工匠、商贩和基层官吏分别使用独立的双帧步行与双帧职业动作素材，HUD 显示当前人流和工作人数
- 住宅五阶段、流民、城门、水井、农场、粮仓、市场、道路和地表全部由版本化手绘文件素材驱动
- 不可见 3D 代理保留精确拾取和占地，运行画面不再用方块/圆柱拼装建筑主体
- 1×1 水井、道路距离场与住宅 5→10 人升级/降级
- 12 tick 一年；小麦、大豆、水稻、粟、白菜按各自生长月与收获月运行，并使用五套独立高保真农田素材
- 分品类粮仓/市场库存、按真实多样性计算清淡/普通/可口/美味，住户保留最近配送品质
- 断路停运、库存保留、补路自愈与确定性最近来源选择
- 2×2 市场从粮仓补货、8 格住宅配送与每户 3 tick 口粮宽限
- 水与口粮共同驱动住宅升级，断供降级、补路恢复与独立缺粮状态
- 季节劳动力、三档工资、农业/商业/公共服务优先级、缺工与薪耗
- 民心与三档工资共同形成可解释迁入吸引力，低吸引力宅基地等待、提高工资后流民恢复迁入
- 九月收麻→织坊加工→市场衣物→住宅衣物储备的守恒产业链
- 兵器作坊→步兵营逐件成军；道路连通城门才计入已部署守军
- 粮仓按作物接收/拒收、神农供奉扣粮与农业祝福、外交赠礼使者与关系门槛通商
- 税务署沿真实道路覆盖住宅；住宅等级、宜居度、税率和官吏缺工共同决定月税，工资与税收进入同一国库
- 轻税/重税、工资与饱腹逐项改变民心，五行风水与周边宜居度保持独立解释
- 音乐学校派出乐师逐格走向市场，只有实际经过门前道路的住宅获得短期娱乐覆盖
- 外交通商后的 3×3 贸易站按实物库存出口衣物，商队收入与工资同月结算；未通商、断路、缺工或缺货均停摆
- 二月新年祭真实消耗一份粮和 20 国库、提升民心并按年份防止重复举办
- 暂停、1×、2×、4× 都驱动同一个 Worker 权威时钟，不存在前端假加速
- 12 tick 跨年能力表、纸张政务/学校礼制/骑兵节点与跨年自动保存
- v1/v2/v3/v4/v5→v6 存档迁移、revision 保序保存与多标签冲突保护
- 地图边界拓扑保护、极限计数原子拒绝与旧城门冲突住宅迁位
- React DOM HUD、Vitest 与 Playwright 验收测试

## 本地运行

要求 Node.js 22.22.3 与 pnpm 10.33.0（版本已通过 `.node-version` 和 Corepack 锁定）。

```bash
pnpm install
pnpm dev
```

然后打开 [http://127.0.0.1:4173](http://127.0.0.1:4173)。住宅、农场、粮仓、市场、麻田、织坊、兵器坊、步兵营、税务署和音乐学校占 2×2，贸易站占 3×3，水井与道路占 1×1，也可用“拆除”逆转建设。住宅先成为宅基地；邻接入口 `(0,15)` 的连通道路后，流民从城门逐格走来，完成地基、木架、封顶和成屋后才入住 5 人并携带 3 tick 口粮；入住者随后转为持续活动的市民代表，沿道路上工、工作和返家，不会在成屋时消失。同时有水和口粮时住宅升到 10 人。农场工具展开五种作物选择，粮仓在 12 步内按接收策略收粮，市场再向 8 步内住宅配送。右侧政策条可调工资、行业优先级、税率、粮仓品类、神农供奉、外交赠礼和新年祭；左下可暂停或切换 1×/2×/4×。Q/E 旋转相机，滚轮缩放，中键或右键拖动平移；画布聚焦后也可用方向键选格、回车建造。

## 验证

```bash
pnpm test:all
```

分项命令：

```bash
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test
pnpm build
pnpm test:e2e
pnpm test:e2e:smoke
```

E2E 会先构建并启动 `dist` 的本地预览，因此验证的是生产构建，不是 Vite 开发服务器。GitHub Actions 会在推送和拉取请求时执行同一套门禁。

首次运行 E2E 前安装 Chromium：

```bash
pnpm exec playwright install chromium firefox webkit
```

## 结构

```text
apps/game-web/          React 壳、真实 Worker、Babylon 入口与 E2E
packages/protocol/      v1～v6 存档、命令、快照和 Worker 运行时边界
packages/simulation/    建筑占用、流民施工、农业物流、劳动力、产业、军事、财政民心、娱乐行者、贸易、宗教外交与年代规则
packages/persistence/   Dexie 迁移、坏档隔离、revision/冲突保护和保存队列
packages/renderer/      Babylon scene、真实素材清单、2.5D impostor、相机、道路和拾取预览
```

美术生产与 Image Gen 复用规则见[美术素材生成与程序切分规范](./美术素材生成与程序切分规范.md)，包含提示词模板、透明底处理、图集/JSON、GLB/动画和资产验收要求。

验收口径见 [第一垂直切片](./第一垂直切片-验收.md) 至 [第八垂直切片](./第八垂直切片-真实运行素材验收.md)，以及本轮的 [《龙之崛起》玩法研究与夜间实现验收](./龙之崛起玩法研究与夜间实现验收.md)；结构决策见各切片对应的结构设计文档。
