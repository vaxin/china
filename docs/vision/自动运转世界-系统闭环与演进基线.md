# 自动运转世界：系统闭环与演进基线

## 一句话定义

世界是一个自主运转的社会经济模拟器，不是等待 Agent 调用的一组工具。

没有玩家、没有 LLM、不再新建建筑时，世界仍然应该持续发生：

- 人会产生需求并消耗资源；
- 家庭会获得收入、支出、储蓄、贫困或迁徙；
- 生产组织会购买投入、招工、生产、定价、盈利或停业；
- 市场会因供需改变成交、价格与缺货状态；
- 物品会真实生产、运输、交易、储存、损耗与消费；
- 政府会征税、支付公共成本、维持服务或陷入财政危机；
- 人口会出生、成长、转职、衰老、死亡和迁徙；
- 天气、季节、疾病、灾害和外部交易会冲击原有平衡；
- 城市可能繁荣、停滞、分化、衰退，也可能恢复。

Agent 之后的价值，是让这些本来就会发生的流程产生更有个性、更长期、更难预测的选择，而不是代替世界运转。

## 世界的最小完整闭环

```text
自然与时间
     |
     v
资源与生产 -----> 商品与物流 -----> 家庭消费与需求
     ^                    |                       |
     |                    v                       v
企业投资 <-------- 市场、价格与货币 <------ 劳动、收入与财产
     |                    |                       |
     +--------------------+----------+------------+
                                      |
                                      v
                              税收与公共服务
                                      |
                                      v
                              健康、迁徙与人口
                                      |
                                      +----> 回到劳动与需求
```

任何一条边是假的，都会破坏实验意义。例如工资不从雇主账户扣除、死亡不减少劳动力、货物不经物流就瞬移，都会让后续 Agent 学会利用一个虚假世界。

## 世界中的核心实体

### 人与家庭

- `Person`：年龄、健康、能力、职业、工作状态、个人需求。
- `Household`：共享住所、库存、货币、财产、抚养关系与联合预算。

当前的“每户 5/10 人 + 一名可见代表”可以作为表现优化，但模拟层最终需要区分人口结构。否则无法形成抚养压力、技能传承、人口老化和家庭财富差异。

### 生产组织

`Enterprise` 不等于建筑。建筑是空间与设备，企业是有账户、库存、雇员、订单、成本和所有权的经济主体。同一建筑可以换经营者，组织可以破产而建筑仍在。

### 物品与服务

- 物品有数量、品质、所有者、位置、保质期与来源。
- 服务不进入库存，但消耗人时、设施容量与货币。
- 生产配方明确输入、劳动、设施、时间、损耗与输出。

### 账户、财产与合约

货币不只是 HUD 上的总数。家庭、企业、政府和组织各有账户；每笔支付必须同时有借方与贷方。工作、交易、租赁、借贷和税收都应落在可履行、可违约的合约上。

## 八个自动运转系统

### 1. 时间、自然与外部环境

提供日历、季节、天气、土地肥力、水、疾病与外部价格。它们不直接决定结果，而是修改生产率、损耗、健康风险与迁徙压力。

### 2. 需求与消费

人和家庭按时间产生食物、水、住所、衣物、健康、安全与社交需求。满足需求真实扣除库存或服务容量；未满足的需求累积为健康、生产力、满意度、死亡和迁移后果。

### 3. 劳动与技能

劳动者提供可用时间和技能，企业发布岗位、工资和排班。匹配后形成雇佣关系。通勤、生病、抚养和公共义务减少真实可用工时。

### 4. 生产与企业

企业根据库存、历史销量、价格、现金和产能生成生产计划，然后购买投入、招工并执行配方。连续亏损会减产、裁员、借款或关闭；盈利可用于扩产、涨薪或分配。

### 5. 市场与价格

买方提交有上限价的需求订单，卖方提交有库存担保的供给订单。市场使用稳定、可重放的撮合规则成交。价格是成交结果，不是系统凭空设定的幸福度修正项。

### 6. 物流与空间

成交只会产生提货或配送任务。道路、距离、运力、携带容量、时间和风险决定交付是否完成。所有权可在成交时或交付时转移，但必须明确且一致。

### 7. 政府、财政与公共服务

政府按规则征税，从国库支付官员、维护、救济、治安和节庆成本。财政不足必须产生服务衰减、欠薪、借贷或税收压力，不能让服务仍免费工作。

### 8. 人口、健康与迁徙

人口变化由年龄、营养、住房、健康、安全、家庭预期和城外机会共同产生。迁入者不是满足阈值后凭空生成的劳动力，而是需要住所、食物、路径和工作机会的新家庭。

## 系统之间真正的“接口”

世界内部不应由一个巨大 `reconcileTick` 随意修改所有字段。各系统通过领域订单、合约和事件对接：

```ts
interface WorldProposal<TPayload> {
  id: string;
  kind: string;
  proposerId: string;
  basedOnRevision: number;
  payload: TPayload;
}

interface WorldTransaction {
  id: string;
  tick: number;
  debits: LedgerEntry[];
  credits: LedgerEntry[];
  inventoryTransfers: InventoryTransfer[];
  obligationsCreated: Obligation[];
}

interface WorldEvent<TPayload> {
  id: string;
  tick: number;
  kind: string;
  causes: string[];
  participants: string[];
  payload: TPayload;
}
```

典型内部接口为：

- 家庭向市场提交 `DemandOrder`，而不是直接减少市场库存；
- 企业向劳动市场提交 `JobOffer`，而不是直接把居民设为已雇佣；
- 撮合产生 `TradeContract`，而不是直接把物品移到买家家中；
- 交易合约产生 `Shipment`，物流完成后才产生库存转移；
- 雇佣合约产生 `WorkAssignment`，真实工时才产生工资和产出；
- 税制产生 `TaxLiability`，实际征收才产生国库收入；
- 需求未满足产生 `NeedDeficit`，人口系统再把累积缺口转化为健康或迁徙后果。

这些就是未来 Agent 可以影响的位置。没有 Agent 时，每类提案由可重放的基线策略自动生成；有 Agent 时，只是用其决定替换某一个提案策略，后续合约、物流、结算和后果不变。

## 每个 tick 的固定阶段

世界使用固定顺序运转，避免“谁先更新谁占便宜”：

1. `clock`：推进时间，生成季节和外部事件。
2. `accrual`：累积需求、折旧、腐败、利息和到期义务。
3. `planning`：各基线策略根据上一个已提交状态生成订单与计划。
4. `matching`：劳动、商品、信贷与服务市场统一撮合。
5. `execution`：执行通勤、工作、生产、运输、服务与消费。
6. `settlement`：原子结算货币、库存、工资、税收、债务与所有权。
7. `consequences`：结算健康、企业存续、迁徙、出生、死亡和公共服务后果。
8. `observation`：生成事件、指标、快照和下一 tick 可见状态。

同一阶段中的提案先全部收集，再一次性裁决，不按实体数组的遍历顺序偷偷改变结果。

## 世界必须维持的守恒与约束

- 物质守恒：除了明确的生产、消费、腐败、损耗和外部进出口，物品不凭空增减。
- 货币守恒：除非存在明确的货币发行/销毁机制，每笔转账借贷相等。
- 时间守恒：同一人同一时段不能既在农场工作又在市场送货。
- 产能约束：设施、工具、原料、技能和工时任一不足都降低产出。
- 空间约束：移动、服务与物流受道路、距离和容量限制。
- 所有权约束：只有所有者或被授权者能出售、赠与、抵押或消耗财产。
- 原子性：支付和交付要么按合约一起成功，要么进入明确的债务/违约状态。
- 因果可追溯：每个变化都指向提案、合约、配方、规则或外部事件。

## 当前项目已经拥有什么

现有代码不是从零开始。已有：

- 确定性 tick 和 Worker 权威模拟；
- 农业季节、多作物生产、粮仓与市场库存；
- 真实道路可达性、通勤、配送与断路后果；
- 劳动优先级、工资档位、税收、国库与民心；
- 食物、麻衣、兵器、娱乐、外交与贸易的部分物理链条；
- 迁入、住宅、岗位、通勤与市民生命线；
- 快照、存档迁移、revision 与验收测试。

但这些仍主要是“城市管理规则的联动”，还没有成为一个完整的自主经济。最大缺口是家庭账户、企业主体、市场订单与价格、真实雇佣支付、所有权、人口生命周期与自动投资/退出。

## 演进顺序

### 世界里程碑 1：家庭生计闭环

给每个家庭真实账户、成员结构、库存与最低需求。工资必须进入家庭账户，食物必须用货币购买并真实消耗。连续缺口产生健康、满意度与迁徙后果。

这是第一优先级，因为没有家庭生计，后面的工作、价格、贫富和阶层都没有动力来源。

### 世界里程碑 2：企业与雇佣闭环

将农场、织坊、市场等建筑的“工位计数”升级为企业、岗位与雇佣合约。企业从自己账户支付工资和投入成本，产出和销售归企业，资金不足时真实停产。

### 世界里程碑 3：订单、价格与物流闭环

用买卖订单和稳定撮合替代当前的固定配送。形成真实价格、支付、物流、缺货、库存积压和利润反馈。

### 世界里程碑 4：人口与财富跨代闭环

加入出生、年龄、抚养、教育/技能、衰老、死亡、财产继承与家庭分合。到这一步，世界才真正能够产生阶层、流动性与长期历史。

### 世界里程碑 5：自动投资、城市变化与外部冲击

基线策略能够根据利润、缺货、人口与财政状态发起建设、扩产、转产、关闭和维修。再加入灾害、疾病、战争压力、外部价格与贸易通道，验证社会的韧性。

## 世界成立的验收标准

不以“功能数量”验收，而以长时间自治运转验收：

1. 从合法初始状态出发，无玩家指令运行 20 游戏年，没有数值溢出、负库存、重复所有权或幽灵人口。
2. 每件商品能回溯生产与消费，每笔货币变动能回溯交易、工资、税收或发行。
3. 改变收成、人口或道路会通过闭环逐步传导至价格、工资、企业和迁徙，而非靠专用 if 直接改指标。
4. 相同初始快照与随机种子得到完全一致的事件序列。
5. 世界可以出现繁荣、缺货、失业、贫困、企业退出、财政危机与恢复，且每种现象都有可解释的因果链。
6. 删除所有 Agent 适配器后，上述验收仍然全部通过。

## 现阶段的最佳下一步

不接 LLM，不先做记忆和对话。下一条新垂直切片应当是“家庭生计闭环”：

1. 一个家庭拥有独立货币余额和食物库存；
2. 一名劳动者完成真实工时后获得工资；
3. 家庭根据库存和可支付能力自动提交食物购买需求；
4. 支付成功后生成配送，到达后才增加家庭库存；
5. 每日/每月真实消耗食物；
6. 没有收入、无法购买或道路中断时，分别产生可区分的饥饿原因；
7. 全过程无需玩家点击，可快照、可恢复、可重放。

这一切片成立后，居民才第一次真正“有生计”，而不只是沿路行走的城市人流。
