# 智能体开放世界：方向与演进基线

## 北极星

这不是一个“NPC 会聊天”的城建游戏，而是一个持续运行的共享社会：

- 每位玩家创造并长期培养一位居民；
- 居民有稳定身份、需求、关系、记忆、承诺、目标和决策风格；
- 玩家提供自己的模型账户与预算，模型参与该居民的关键决策；
- 居民的选择在同一个稀缺资源、制度和历史共存的世界中产生后果；
- 有趣性来自可理解的性格冲突、合作、声誉、组织与制度演化，而不是随机文本。

## 核心架构原则：世界确定，心智生成

> 前置原则：世界先于 Agent。没有任何 LLM、没有玩家在线时，世界也必须能自主运转。Agent 不负责让世界活起来，只在未来替换或干预世界中已存在的局部决策函数。自动运转世界的设计见[《自动运转世界：系统闭环与演进基线》](./自动运转世界-系统闭环与演进基线.md)。

LLM 不能直接修改世界。LLM 只能在世界提供的候选行动中提交结构化意图，权威模拟层负责验证前置条件、执行动作和产生后果。

```text
世界事件 -> 居民感知 -> 相关记忆 -> 关键决策请求
                                        |
                                        v
                              玩家提供的 LLM
                                        |
                                        v
                               结构化行动意图
                                        |
                                        v
                        规则验证 -> 执行/拒绝 -> 新事件
```

这条边界保证：

- 模型超时或下线时，世界仍能继续；
- 不同价格和能力的模型不能绕过游戏规则；
- 每个后果都能回放到“当时看到什么、想做什么、世界为何接受”；
- 经济、移动、物品和时间仍可测试，生成性被限制在决策而非数值造假。

## 应当建立的五层能力

### 1. 权威世界层

将当前浏览器 Worker 中的权威模拟逐步迁移为服务器中的“房间/世界进程”。所有行动使用命令进入，用事件记录结果，周期性生成快照。客户端只做预测和表现。

现有 `protocol -> simulation -> worker -> renderer` 分层应保留，先抽出运行时边界，再替换传输，不需要推倒重写模拟规则。

### 2. 居民心智层

每个居民至少拥有：

- `identity`：不变的身份、背景与价值观种子；
- `drives`：生存、安全、归属、地位、好奇等可量化驱动；
- `goals`：带优先级、期限、状态和来源的长短期目标；
- `relationships`：对其他居民的信任、亲密、恐惧、义务与最后互动；
- `memories`：事件记忆、压缩反思和可追溯来源；
- `commitments`：承诺、契约、组织规则和社会角色；
- `decisionPolicy`：使用哪个模型、预算、决策频率与失败降级策略。

记忆必须分成“世界事实”和“居民信念”。居民可以误解、遗忘或被欺骗，但不能因此改写客观世界。

### 3. 决策与推理网关

网关屏蔽 OpenAI 兼容 API、本地模型和其他供应商差异，对世界只暴露统一决策契约。

```ts
interface DecisionRequest {
  decisionId: string;
  worldRevision: number;
  citizenId: string;
  situation: PerceivedSituation;
  relevantMemories: MemoryExcerpt[];
  activeGoals: Goal[];
  availableActions: AvailableAction[];
  deadlineAt: string;
}

interface DecisionIntent {
  decisionId: string;
  actionId: string;
  arguments: Record<string, unknown>;
  publicReason: string;
  confidence: number;
}
```

推理必须异步化，且有超时、重试、幂等、限流、用量记账和降级策略。决策请求携带 `worldRevision`；结果返回时若世界已变，必须重新验证或放弃，不能盲目落地过期决策。

### 4. 社会系统层

先做能形成闭环的社会原语，不先做无限自由文本：

1. 交谈与传话；
2. 赠与、交换与拒绝；
3. 请求、承诺、履约与背叛；
4. 合作完成工作；
5. 建立组织、规则和处罚；
6. 声誉与信息传播。

每个社会行动都需要可见的资源或关系后果，否则会退化为一群没有代价的聊天机器人。

### 5. 观测与实验层

“社会学实验”首先是游戏中的可观测模拟，不默认声称具有现实世界科学效度。应当原生记录：

- 决策请求、结构化结果、所用模型和成本；
- 居民当时可见信息与被召回的记忆；
- 意图被接受或拒绝的规则原因；
- 关系网、资源分布、组织、冲突和制度的时间线；
- 可匿名导出的事件数据和可重放快照。

## LLM 应当何时出场

不在每个 tick 调用 LLM。移动、吃饭、路径寻址、工作动画等执行性行为仍由确定性模拟完成。

LLM 参与的“关键决策”包括：

- 多个目标发生冲突；
- 出现新机会、威胁或重要信息；
- 需要对他人作出承诺、欺骗、信任或背叛选择；
- 日程或长期计划到期；
- 玩家介入或要求居民反思；
- 累积经验达到反思阈值。

这能让玩家购买的模型真正决定“他成为什么样的人”，而不是浪费在每走一格路上。

## 用户自带模型（BYOM）的边界

- API 密钥不进入存档、提示词、日志或客户端快照。
- 生产多人世界中，密钥应由独立凭证保管层加密持有；完全客户端调用只适合本地单机原型。
- 用户可配每日/每月预算、最大单次成本、模型和降级模型。
- 用量按居民和决策类型审计，预算用尽后进入明确的低频模式，不伪装为仍在使用高级模型。
- 模型差距应表现为计划、语言和社会判断差异，不能直接购买数值战力或规则豁免。

## 从当前工程演进的顺序

### 智能体里程碑 A：“一个可解释的居民”

目标不是立即连真实 LLM，而是在当前固定状态机与未来模型之间建立稳定契约。

1. 将“每户一个市民代表”升级为持久居民档案：姓名、性格倾向、驱动、当前目标。
2. 建立 `DecisionRequest -> DecisionIntent -> ActionOutcome` 领域契约。
3. 先用可重放的本地决策提供器，在“工作 / 休息 / 访问市场”中做选择。
4. 保留现有状态机作为意图执行器，不让决策层自己移动坐标。
5. 新增居民详情页的“此刻所知 / 正在追求 / 上次选择 / 结果”。
6. 决策、结果、居民档案随存档完整恢复。

验收不看“文本像不像人”，而看同一快照能否重放出同一选择、非法意图能否被拒绝、玩家能否说清居民为何如此行动。

### 智能体里程碑 B：“真实模型接管一个关键决策”

加入一个服务商适配器、结构化输出验证、超时降级、成本记录和完整回放。只选一类高价值决策，例如“粮食短缺时帮助邻居还是囤积”。

### 智能体里程碑 C：“关系与承诺闭环”

支持相遇、交谈、请求、承诺、履约/违约和关系变化。限制在 8～20 位居民的小社会中，验证一条信息或冲突能否穿过多个居民产生后果。

### 智能体里程碑 D：“共享世界”

把世界运行时移至服务器，引入身份、居民所有权、指令权限、断线恢复、事件流与快照。先做小规模、邀请制、异步持续世界，再扩容。

### 后续：组织、制度与多世界实验

当关系与承诺闭环证明好玩后，再引入家庭、行会、宗族、官职、选举/任命、规则提案和惩罚。多世界使用相同初始条件与不同模型/制度参数，用于比较演化路径。

## 暂时不做

- 不让 LLM 生成任意代码或直接访问数据库；
- 不把自由聊天当成“智能居民”已经成立；
- 不在社会闭环尚未成立时追求数百或数千智能体；
- 不让玩家花费更高模型成本就直接获得规则外能力；
- 不在没有同意、匿名、数据保留与导出规则时对外宣称开展人类社会学实验。

## 方向验证指标

前期最重要的不是 DAU，而是：

- 玩家能否只看决策史就识别自己的居民；
- 相同事件对不同居民是否产生稳定但不同的选择；
- 有多少事件在没有编剧指定的情况下被多人转述、放大或改变；
- 承诺履行率、关系网稳定性、组织寿命与资源不平等如何随时间变化；
- 每个有效关键决策的成本、延迟、失败率和降级率；
- 玩家是否愿意回来查看“我的居民在我离开后成为了谁”。

## 研究参照

- Stanford/Google 的 Generative Agents 证明了观察、记忆、反思与计划的组合对可信行为很关键：<https://arxiv.org/abs/2304.03442>
- Project Sid 展示了 10～1000+ 智能体中角色分化、共同规则与文化传播的可能性，也说明大规模需要专门的并行编排：<https://arxiv.org/abs/2411.00114>
- AI Town 是值得对照的 TypeScript 共享状态、模拟引擎、向量检索与多模型适配实现：<https://github.com/a16z-infra/ai-town>
