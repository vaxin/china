# 可编程宏观物理世界：核心架构设计

## 1. 架构结论

世界不尝试从粒子层还原现实物理，也不为房屋、食物、胶水、发动机等事物预设类型和配方。

世界由两部分构成：

```text
极小且不可绕过的世界内核
  +
由代码定义行为的宏观物体
```

每个物体都是一个有形、有资源账本、有内部状态、有输入输出端口的程序实体。物体代码决定它面对输入时希望产生什么宏观效果；世界内核验证位置、权限、物质、能量、动量、时间和计算预算后，原子提交或拒绝这些效果。

核心原则：

> 程序决定行为，内核结算现实。

这是一种“宏观因果可编程宇宙”。它追求的是开放的功能组合和文明创造，而不是对现实微观物理的近似复刻。

## 2. 世界观含义

在这个宇宙里，物体的性质本质上是函数：

```text
输出效果 = 物体程序(输入事件, 自身状态, 局部观察)
```

同样的物质可以因为结构和行为程序不同而成为墙、容器、燃料、工具或机器。智能体能够创造开发者没有预设名称的物体，只要程序的所有外部效果都通过世界内核结算。

这意味着科学也与现实略有不同：

- 自然科学研究不可变的世界公理、效果成本和既有物体的行为。
- 工程科学通过编写、组合和验证新的物体程序，创造新的宏观规律。
- 计算机出现之前，“代码”表现为结构、工艺和不可变的被动物性程序；文明拥有可写计算载体后，才出现可在世界内更新的控制程序。

## 3. 非目标

第一阶段明确不做：

- 全城市粒子、原子或分子模拟。
- 由大模型直接修改权威世界状态。
- 固定建筑枚举、固定科技树或固定配方表作为新内核基础。
- 允许物体代码直接写入其他物体内部状态。
- 执行未经验证的 JavaScript、访问网络、文件系统或宿主环境。
- 让所有物体逐帧运行代码。

## 4. 不可编程的世界公理

开放性建立在少量不可修改的边界上。第一版内核只拥有以下权威：

### 4.1 身份与因果

- 每个物体有稳定 ID、程序版本、创建来源和事件历史。
- 所有变化都由带顺序的事件触发并产生新 revision。
- 同一初始状态、命令序列和世界种子必须得到相同结果。
- 过去事件不可由物体程序覆盖或重写。

### 4.2 空间与局部性

- 物体有位置、方向、占据体积和碰撞代理。
- 接触、施力、搬运和物质转移默认要求空间邻近或端口连接。
- 远程作用必须通过有位置、带宽和传播时间的信号或连接实现。
- 程序不能把物体瞬间移动到未连接位置。

### 4.3 物质账本

- 每个物质单位只属于一个物体、库存或转移中的托管区。
- 分割、组合和制造只能重新归属已有物质，不能复制或删除。
- “销毁物体”只能把它转换成废料、能量或其他有账本归属的实体。
- 物质携带来源链；名称和用途由程序与社会赋予，不由内核枚举。

### 4.4 能量、动量与不可逆成本

- 主动运动、持续输出、计算、变形和信号传输必须支付能量。
- 碰撞与施力由内核结算动量，程序不能注入无来源冲量。
- 总能量守恒；不可逆操作至少产生规定的废热或可用能损失。
- 对外效果有功率上限，不能把有限能量在零时间内全部释放。

第一版可以将能量抽象为“可用能 + 废热”，而不是立即模拟全部现实能源载体。新的能源形态可以由物体程序包装，但最终必须落回这两个内核账本。

### 4.5 信息与计算

- 程序代码、内部状态、传感精度、执行频率和通信带宽都占用物理实现容量。
- 可写控制程序的每次执行消耗指令预算和能量，并产生废热。
- 程序不能获得未通过传感器、端口或所有权暴露的信息。
- 随机性只能通过内核提供的确定性随机源获得。

### 4.6 权限

- 物体程序只能直接写自己的内部状态。
- 其他物体只能通过碰撞、公共端口、信号、连接或内核强制事件受到影响。
- 所有者可以授权控制权、读取权和连接权，但不能授权违反守恒。
- 被窃取、强拆和攻击不是简单“无权限拒绝”，而是由接触、施力和对象响应共同结算。

## 5. 通用物体模型

新内核不再以 `typeId: "house" | "market" | ...` 作为世界本体。所有世界事物使用同一个对象结构：

```ts
interface WorldObject {
  id: string;
  parentId: string | null;
  ownerId: string | null;
  transform: Transform;

  geometry: GeometryDescriptor;
  collision: CollisionProxy[];

  matter: MatterLedger;
  energy: EnergyLedger;
  information: InformationCapacity;
  implementation: ImplementationEnvelope;

  constitutiveProgram: ProgramRef;
  controllerProgram: ProgramRef | null;
  programState: Uint8Array;

  ports: PortInstance[];
  children: string[];
  schedule: WakeSchedule;
  revision: number;
}
```

`ImplementationEnvelope` 不是“木头强度”“钢铁硬度”这类材料枚举，而是一组所有对象共用的外部能力上限：

```ts
interface ImplementationEnvelope {
  maxForce: number;
  maxImpulsePerEvent: number;
  maxPower: number;
  maxMatterThroughput: number;
  maxSignalBandwidth: number;
  maxStateBytes: number;
  minFeatureSize: number;
  maxCollisionProxyCount: number;
}
```

程序可以在包络内任意安排响应，也可以通过杠杆、蓄能、串并联和时间交换重新组合能力，但不能自行把包络数值写大。持续性能力必须由制造过程写入并由对应物质、结构、信息载体和工具能力背书。

### 5.1 几何与碰撞分离

- `geometry` 保存渲染、编辑和文化表达需要的形状，可以非常复杂。
- `collision` 是运行时编译出的球、盒、胶囊、凸体或少量组合体。
- 物体程序可以请求改变自身几何；内核重新编译碰撞代理并检查体积、物质和空间冲突。
- 内部细节默认不参与外部碰撞，除非被暴露为独立子物体或交互端口。

### 5.2 两类程序

**构成程序（constitutive program）**描述物体是什么：碰撞时怎样响应、何时损坏、如何吸收输入、如何暴露端口。它在制造后不可直接改写；改变它等于重新制造或改造物体。

**控制程序（controller program）**描述物体主动做什么：读取传感器、处理信号、按时间调节输出。只有包含可写计算载体的物体才能安装或修改控制程序，并承担计算能耗。

这样，古代房屋和胶水也可以由代码模拟，但这些代码只是世界对其被动物性的权威描述，不意味着古人拥有可编程计算机。文明造出计算载体后，AI 的 vibe coding 才成为世界内可部署的软件能力。

## 6. 程序运行契约

物体程序运行在确定性沙盒中，推荐采用受限字节码或经过验证的 WASM 子集，不直接执行生成式 JavaScript。

```ts
interface ObjectProgram {
  manifest: ProgramManifest;
  onEvent(context: ReadonlyContext, event: ObjectEvent): EffectProposal[];
}
```

`ReadonlyContext` 只包含：

- 自身公开状态和程序私有状态。
- 当前事件携带的数据。
- 传感器已经取得的局部观察。
- 当前账本余额、端口和剩余执行预算。
- 内核提供的确定性时间与随机能力。

程序禁止：

- 获取全局对象列表。
- 读取其他对象私有状态。
- 直接修改世界或其他对象。
- 创建线程、网络请求、文件访问和宿主系统调用。
- 在一个事件中无限循环或递归生成事件。

### 6.1 运行清单与包络

每个程序在部署前必须声明可静态检查的运行包络：

```ts
interface ProgramManifest {
  codeHash: string;
  codeBytes: number;
  maxStateBytes: number;
  maxInstructionsPerEvent: number;
  maxEventsPerWorldHour: number;
  maxEffectRate: EffectRateEnvelope;
  requiredPorts: PortDefinition[];
  collisionProxyBudget: number;
  minimumFabricationPrecision: number;
}
```

包络不是科技名称，而是实现复杂度：程序大小、状态量、响应速度、最大功率、端口数量、几何精度。制造工具是否能实现该程序，只比较这些客观能力。

## 7. 世界效果 ABI

效果 ABI 必须语义贫瘠但组合完备。内核不提供 `heal`、`makeFood`、`buildHouse`、`teleport`、`researchComplete` 等高级效果。

第一版效果集合：

```ts
type EffectProposal =
  | WriteOwnState
  | ReplaceOwnGeometry
  | SplitOwnMatter
  | TransferMatter
  | SpawnChildObject
  | MergeOwnedObjects
  | TransferEnergy
  | ConvertEnergy
  | ApplyImpulse
  | CreateBond
  | BreakBond
  | EmitSignal
  | OfferPortExchange
  | ScheduleWake;
```

### 7.1 自身状态

- 程序只能写自己的 `programState`。
- 状态大小不能超过制造时提供的信息容量。
- 状态写入和高频更新受执行预算限制。

### 7.2 物质

- `SplitOwnMatter` 从自身账本切分物质并创建有来源链的子对象。
- `TransferMatter` 必须通过接触、容器或连接端口进入托管。
- `MergeOwnedObjects` 只能合并已经实际邻接且获授权的对象。
- 生成物继承输入物质，不能只返回一个没有来源的名称。

### 7.3 能量

- 物体只能输出已持有或本事件输入的能量。
- `ConvertEnergy` 必须满足内核的总量、功率和废热约束。
- 定时器、信号、主动控制和持续输出都需要能量来源。

### 7.4 力与碰撞

- 碰撞检测和最小分离由内核负责。
- 双方构成程序可以提出弹性、吸收、反射、连接或形变响应。
- 内核统一求解冲量，保证双方动量变化相反、总能量不增加。
- 超过程序声明包络或可用资源的响应被截断或进入程序声明的失效分支。

### 7.5 连接

`CreateBond` 创建的是有位置、有强度包络、有维护状态的连接边，不模拟微观黏附：

```ts
interface Bond {
  id: string;
  objectA: string;
  objectB: string;
  anchors: [LocalPoint, LocalPoint];
  maxImpulse: number;
  maxTorque: number;
  controller: ProgramRef | null;
}
```

胶、绳、铰链、轴承、锁、焊接和机械关节都可以由“连接边 + 程序”表达，无需进入内核成为新类型。

### 7.6 信息与开放协议

- 内核只负责有距离、带宽、延迟和权限的字节传递。
- 端口协议 schema 由对象程序自行定义，并以内容哈希标识。
- 新机器可以创造新的通信协议；旧机器除非实现兼容端口，否则无法理解。
- 信号不能直接修改接收方，接收方程序决定如何响应。

## 8. 双边交互与原子结算

对象 A 不能通过代码直接修改对象 B。一次交互按以下流程运行：

```text
内核生成事件
  → A、B 分别读取各自视角并提出效果
  → 相关物质/能量进入临时托管
  → 检查空间、权限、守恒、程序包络和端口协议
  → 解决双方冲突与冲量
  → 原子提交全部效果，或整体拒绝
  → 写入可复放事件日志
```

交互分两类：

- **强制物理事件**：碰撞、被推动、失去支撑等，不需要目标同意，但必须由内核结算。
- **协议交互**：交易、装载、控制、数据交换等，需要端口匹配和目标程序接受。

同一 revision 内的冲突使用稳定排序：事件时间、因果父事件、对象 ID、提案序号。不得由线程调度决定结果。

## 9. 防止“写一句代码就获得神力”

只做守恒还不够。若 Agent 开局就能把任意复杂程序无成本写入一块石头，技术进步仍会坍缩。因此必须区分“设计出来”和“在世界中实现”。

### 9.1 设计是知识，不是实体

AI 可以随时生成源代码、测试和蓝图，但它们首先只是 `DesignArtifact`：

```ts
interface DesignArtifact {
  sourceHash: string;
  manifest: ProgramManifest;
  requiredMatter: number;
  requiredEnergy: number;
  requiredPrecision: number;
  requiredStateBytes: number;
  requiredInstructionsPerWorldHour: number;
  requiredPorts: PortDefinition[];
  evidence: ExperimentRecord[];
}
```

设计本身不会改变现实。

### 9.2 制造能力是连续约束

工具和工坊也是可编程物体，它们的端口声明可实现范围：

```text
最大加工体积
最小结构精度
可写状态容量
可实现程序大小
可持续计算速率
最大输入/输出功率
可用端口和执行器
制造时间、物质与能量
```

设计只有被某个制造过程完整承载，才能实例化成世界对象。不存在“青铜时代”“电气时代”布尔值；文明进步表现为制造工具的能力包络逐步扩大。

制造不是凭空签发更大的包络。新对象的实现包络必须满足：

- 不超过制造工具自身可输出的精度、功率、吞吐与信息容量。
- 锁定或消耗设计声明的物质、能量、工时和信息载体。
- 若通过杠杆、齿轮、蓄能等方式放大某个维度，必须在距离、速度、时间或其他维度上付出对应代价。
- 多个对象组合后的包络由内核按连接与程序推导，不能由父对象随意声明。

### 9.3 复杂度必须物理化

- 更精细几何需要更高加工精度和时间。
- 更多程序状态需要更多信息载体。
- 更快控制需要更高计算速率与能耗。
- 更大力、更高吞吐量需要更高功率和结构包络。
- 复制设计仍要支付制造成本；知识传播不能复制物质与能源。

这使 AI 可以提前想出远超时代的方案，但无法在缺少工具、能源和精度时把它直接变成现实。

### 9.4 世界创世与能力来源

世界必须有有限的初始条件：人类身体、自然地形、原始物质、火、水和少量简单工具以已经实例化的对象进入世界。它们拥有由世界种子签名的构成程序和实现包络，但不是开发者为未来科技列出的完整物品表。

文明只能从这些初始能力出发，通过组合、拆分、积累能量、提高精度和制造更强工具递归扩张能力。任何无法追溯到创世对象、既有制造工具和实际资源的实现包络都被内核拒绝。这样，开放创造有明确起点，但没有预写终点。

## 10. 组合、封装与重新编译

任意对象都可以由其他对象组成。组合不是把所有子程序永久逐帧运行，而是形成层级对象：

```text
子对象与连接图
  → 组合编译
  → 父对象碰撞代理
  → 汇总账本
  → 编译后的事件路由
  → 对外暴露的少量端口
```

父对象保留子对象和连接信息，以便编辑、拆解、损坏和继承来源，但运行时只激活与当前事件相关的路径。

例如一座房屋可保留一千个构件，却在通常状态下表现为：

- 若干碰撞盒。
- 室内/室外端口。
- 门、火炉、储物等活跃子对象。
- 一个处理雨水、热量和局部损坏的构成程序。

当墙体被拆除时，只展开该区域的子对象、重新计算碰撞代理和端口连通，不重新运行整座城市。

## 11. 调度与性能模型

### 11.1 默认休眠

物体没有逐帧 `tick()` 权利。程序仅在这些条件下唤醒：

- 收到碰撞、端口、信号或所有权事件。
- 自己预约的定时器到期。
- 处于移动或持续输出状态。
- 相邻空间索引发生与其订阅条件相关的变化。

要求更高唤醒频率意味着更高的清单包络、模拟指令预算和世界内计算能耗。

### 11.2 空间索引

- 静态碰撞代理进入分块 BVH 或空间哈希，不运行代码。
- 运动物体只查询附近候选对象。
- 大型复合对象按接触区域路由事件，不广播给全部子对象。
- 视野、信号和端口连接使用独立索引，避免所有系统共享全局扫描。

### 11.3 事件风暴限制

- 每个程序有单事件指令预算、单位世界时间事件预算和效果速率包络。
- 每个因果链有最大同步深度；超过部分排入后续世界时刻。
- 派生对象必须锁定真实物质和信息容量，阻止指数级无成本复制。
- 故障程序进入熔断状态，保留错误事件，不拖垮 Worker。

### 11.4 成本目标

运行成本应近似：

```text
活跃运动对象
+ 当前碰撞候选
+ 本时刻被唤醒的程序指令
+ 已提交效果数量
```

而不是世界对象总数。城市可以保存大量休眠对象，但活跃预算必须通过基准测试确定，不能在设计稿中凭空承诺数字。

## 12. 安全、确定性与版本

- 程序代码按内容寻址并不可变；修改得到新 hash。
- 保存文件记录代码 hash、清单、状态和来源，不能只记录用户给出的名称。
- 运行时只加载通过 verifier 的字节码。
- verifier 检查禁止指令、资源上界、可终止性约束和 ABI 版本。
- 每次效果结算产生包含输入、提案、拒绝原因和账本差额的事件。
- 程序升级需要明确迁移函数，并在沙盒中先验证旧状态到新状态的转换。
- 世界内核与效果 ABI 有独立版本；旧程序必须可重放或经过显式迁移。

## 13. 人类智能体如何进入这个世界

每个人由三个彼此隔离的部分组成：

```text
System Prompt 与记忆：决定思想和决策
人类身体对象：执行生理、感知和物理限制
行动桥：把心智意图转换成身体端口请求
```

System Prompt 不能改写身体程序。身体向心智输出饥饿、疼痛、疲劳、温度、可见物体和接收到的语言；心智只能通过移动、抓取、说话、使用工具等端口控制身体。

人类身体的构成程序在开局是受保护的既有自然对象。文明若要义肢、脑机接口、机械身体或意识迁移，必须制造与身体/心智桥兼容的端口、载体和控制程序，并承担相应的物质、能量、信息容量和风险。

## 14. 科学创新流程

世界不判断一个想法“是否像现实科技”，只判断它能否被实现并通过实验。

```text
发现问题
  → 编写行为程序、蓝图和测试
  → 静态验证程序与资源包络
  → 在沙盒或小样中运行
  → 使用现有工具制造
  → 在真实世界事件中观察
  → 失败、修订或形成可复制设计
  → 传播代码、证据和制造方法
```

一个发明的完整知识不是一句描述，而是：

- 源代码与程序 hash。
- 输入/输出端口协议。
- 资源与制造包络。
- 测试用例和实验记录。
- 已知失败条件。
- 可复制的制造过程。
- 作者、所有权、许可证或保密状态。

社会可以围绕这些对象形成专利、开源、垄断、标准、逆向工程和兼容性竞争，而无需内核预设这些制度。

## 15. 示例

### 15.1 胶

胶对象在接触两个表面并满足固化时间后请求 `CreateBond`，支付自身物质和能量。连接强度、响应速度和最大面积必须落在程序清单与制造能力包络内。连接断裂时，胶的程序决定残留物如何归属。

### 15.2 水泵

水泵不调用 `pumpWater()`。它通过入口端口接收物质托管，消耗可用能，再从邻近出口端口提交 `TransferMatter`。流量受程序效果速率、端口容量和输入功率限制。

### 15.3 炉灶

炉灶接收燃料对象，把其可用能转换为局部热输出并产生废热。锅、食物和人体分别收到热事件，由各自构成程序决定状态变化。内核不认识“烹饪完成”。

### 15.4 新材料

新材料是“物质账本 + 几何 + 构成程序 + 制造证据”的新版本。它可以表现出未被开发者命名的碰撞、连接、热响应或信号性质；只要每次外部效果经过统一结算，就不需要向内核添加材料类型。

### 15.5 恶意永动机

程序请求持续输出冲量和能量，但没有对应输入或自身余额。内核拒绝效果，并记录 `insufficient-energy`。程序即使隐藏循环、改名或通过多个子对象转发，也无法绕过每次原子结算的总账。

## 16. 与现有原型的迁移

现有架构已经具备两个可复用边界：

- `apps/game-web/src/simulation.worker.ts` 是权威执行入口。
- `packages/protocol` 对命令、快照和存档进行严格校验。

但当前世界仍以固定 `BuildingView` 联合类型、固定 `GameCommand` 和聚合住户为核心。迁移应并行推进，不直接推翻已经运行的城市。

### 阶段 A：独立内核实验室

新建独立的可编程世界内核包，不接入城市画面。完成：

- 通用对象、程序清单、资源账本。
- 确定性沙盒和 verifier。
- 效果提案、托管、结算与事件日志。
- 定时器、信号、物质/能量转移、冲量与连接。

### 阶段 B：同一 ABI 的四个样例

在不修改内核效果集合的情况下，仅通过不同程序实现：

1. 可连接两个物体的胶。
2. 消耗能量搬运物质的泵。
3. 转换能量并输出热的炉灶。
4. 接收信号控制连接状态的门。

如果需要为其中任何一个新增语义效果 API，说明 ABI 仍然不够基础或对象边界设计有误。

### 阶段 C：恶意程序与性能验收

- 质量复制、能量复制、越权写状态、无限生成、无限循环全部被拒绝或熔断。
- 相同事件日志可完全重放。
- 大量休眠对象不会线性消耗程序执行时间。
- 复合对象封装前后对外端口行为一致。

### 阶段 D：接入城市的一处真实场景

先把“炉灶—燃料—容器—人体取暖”做成可编程对象链，与现有人类活动并存。现有房屋、市场和产业系统暂时保留，直到新内核证明可以承担一个完整生存闭环。

### 阶段 E：逐步替换固定类型

- 固定建筑迁移为对象模板和程序版本，而非立即删除旧存档。
- `WorldSnapshot` 增加可选的对象、程序和账本区段，保存格式单独升版。
- `GameCommand` 增加通用对象操作和效果请求，旧命令通过适配器继续工作。
- 渲染器从 `typeId` 素材映射逐步转向对象几何描述和外观程序。

## 17. 第一条实现切片的验收标准

第一条实现切片只证明内核成立，不追求完整城市：

1. 世界内核完全不知道“胶、泵、炉灶、门”这些名称。
2. 四个样例只使用同一组底层效果完成各自功能。
3. 修改程序即可产生新的宏观行为，不需要修改模拟器源码。
4. 所有输出都能在物质、能量、动量、时间和权限账本中解释。
5. 程序不能直接修改其他物体状态。
6. 程序超预算、死循环或制造事件风暴时被确定性熔断。
7. 组合对象能够封装子对象，并在受损时局部展开。
8. 快照保存、恢复和事件重放结果一致。
9. 设计代码与世界实体严格分离：未制造的设计不会改变现实。
10. 现有城市原型无需一次性迁移即可继续运行。

## 18. 仍需通过原型回答的问题

这些问题不能靠文档拍脑袋，需要用第一条切片测量：

1. 效果 ABI 是否足以表达四个样例，又没有偷偷引入高级语义。
2. “可用能 + 废热”的账本是否足够，还是必须增加势能和更多能量载体。
3. 构成程序的效果包络如何静态验证，哪些边界必须在运行时结算。
4. 制造精度、程序复杂度和响应功率如何映射成连续成本而不成为隐藏科技树。
5. 复合对象编译到什么粒度才能同时保留可编辑性与性能。
6. 受限 WASM 与专用 DSL 哪一个更适合确定性、验证和 AI 生成。
7. 人类身体应暴露哪些最小端口，才能允许未来医学和身体改造而不提供 `heal` 捷径。

这些不是设计失败，而是新内核第一阶段应主动验证的研究问题。只有原型数据能决定最终取值。
