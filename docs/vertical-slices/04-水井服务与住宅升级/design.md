# 第四垂直切片：结构设计

## 版本与数据

- 冻结 v1/v2 的 house-only 类型和 Zod schema，不再引用 current `BuildingView`。
- 当前 v3 `BuildingView` 为 `house(level 1|2, 2×2)` 与 `well(1×1)` 的 discriminated union；住户人数为 5 或 10。
- v1/v2→v3 迁移补默认等级，不改变 tick、revision、ID、道路或旧住户；若旧住宅压住后来新增的城门格，则确定性迁到最近合法 2×2 空地；读取后事务内原位回写 v3。
- IndexedDB 表结构未变，因此 Dexie database version 不变；存档格式版本与数据库 schema version 分离。

## 水服务距离场

1. 收集所有水井四边相邻道路格作为多源 BFS 的距离 0。
2. 在全部道路格上正交传播，最大距离 8。
3. 住宅四边任一道路格存在距离 ≤8 即有水。
4. 距离场是 tick 内派生数据，不落盘；32×32 全量重算为 O(道路 + 建筑)。

## 状态相位

- tick 开始时已有的一级 5 人住宅获得水：升二级并改为 10 人。
- 当 tick 才迁入的住宅先保持一级 5 人，下一 tick 才可升级。
- 删除道路仍立即迁出失去城门连接的住户。
- 删除水井后立即重算现有二级住宅：失去全部水服务则降一级并缩为 5 人；不新增或升级住宅。

## 不变量

1. 全部 house/well ID 唯一、占地不重叠、不压道路和城门。
2. 住户只能引用 house；一级容量 5、二级容量 10。
3. 有住户的住宅必须具备城门道路连接；二级住宅必须具备有效水服务。
4. 快照按建筑 ID、道路 key、住户 houseId 稳定排序。
5. 表现层仅渲染井、等级和人口，不参与服务判定。
6. BFS 在计算 tile key 前判定地图边界，左右边缘不会环绕到相邻行；计数耗尽时命令原子拒绝，仍返回可保存快照。
