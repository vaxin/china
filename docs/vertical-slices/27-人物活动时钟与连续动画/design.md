# 第二十七垂直切片：人物活动时钟与连续动画结构设计

## 决策

保留 Worker 权威人物状态，但把人物推进从月度 `advance-time` 拆为独立 `advance-activity` 命令。世界月份负责生产与经济，人物活动脉冲负责道路移动、工作/休息拍数、巡视和任务行者推进；Babylon 仅负责两个权威道路点之间的连续表现。

## 时钟与数据流

```text
现实时间
  ├─ 世界时钟：10s / 月（受暂停、1×、2×、4×影响）
  │    └─ advance-time → 经济、粮食、税收、生产、建造阶段
  └─ 人物时钟：2.4s / 活动脉冲（只受暂停影响）
       └─ advance-activity → 市民、流民、乐师道路格与动作状态
                                    ↓
                              WorldSnapshot
                                    ↓
                   Babylon 约 2.2s 连续插值 + 每帧姿势循环
```

活动命令采用单飞机制；上一笔未完成时不叠加、不追赶。活动响应只更新内存快照，不逐脉冲写 IndexedDB；下一次月度结算或玩家操作会保存最新人物状态。

## 模块边界

### `packages/protocol`

- 增加严格的 `advance-activity` 命令，`pulses` 为 1～10 的正整数。
- 不改变 v6 人物快照形状，继续使用 `state` 与状态内 `dwellTicks`。

### `packages/simulation`

- `advanceActivityPulses`：不改变 `world.tick`，只协调人物活动。
- 市民：岗位分配、通勤、工作、返家、休息、巡视、等待。
- 流民：活动脉冲只负责走路和抵达后切为施工；月度 tick 只推进施工阶段。
- 乐师：活动脉冲负责沿路移动与沿途服务；月度 tick 负责服务衰减和派出。
- 只有可观察人物状态变化时才增加 revision。

### `apps/game-web`

- 世界时钟与人物活动定时器各自单飞。
- 暂停同时阻止两类权威命令，并通知 renderer 冻结动作相位。
- 人物脉冲不触发逐步自动保存，避免高频 IndexedDB 写入。

### `packages/renderer`

- 人物实例永久由稳定 key 复用；`resting` 不再过滤。
- 目标变化从当前屏幕脚点继续插值，不回跳逻辑格。
- 移动到工作/休息状态时使用 `pendingAction`，抵达后才切动作。
- 每个职业只加载一张 `4×8` 步行 sprite sheet，通过 UV 行列切片选择四个道路方向与八帧步态；不再为每帧创建独立纹理材质。
- sheet 行顺序固定为 `south-east / south-west / north-west / north-east`，列顺序固定为同一完整步态的 `0...7`；移动向量先映射到方向行，再由人物独立相位选择帧列。
- 所有格子尺寸一致，共用 bottom-center pivot、脚底基线和透明 padding；素材 QA 必须检查越格、裁脚、人物比例漂移、工具穿帮与键色残边。
- 行走姿势由 sprite 帧、步态起伏、重心摆动与行进朝向共同构成；减少动效时保留位移并降低帧频、移除摆动。
- 暂停时冻结插值与动作帧时间，恢复时平移内部时间基准。

## 状态节奏

- 人物活动脉冲：2400ms。
- 道路格视觉过渡：2200ms，留约 200ms 接地收步。
- 工作：6 个活动拍后返家，约 14.4 秒；期间职业动画持续循环。
- 休息：3 个活动拍后重新上工或巡视，约 7.2 秒。
- 巡视：以 `dwellTicks` 作为状态内相位，向外最多 3 步后沿最短路折返，循环往复。

## 兼容与故障处理

- 旧 v6 的 `dwellTicks` 继续合法；超出当前节奏的值按倒计时逐步归零，不静默改存档。
- 拆路后，已开始的单格视觉过渡自然收尾；下一活动脉冲不再取得断路目标。
- 后台节流不按现实时间补发活动脉冲，因此恢复前台不会连续跨格。
- 人物活动命令失败只报告一次可定位错误，不阻塞下一次世界月度结算。
