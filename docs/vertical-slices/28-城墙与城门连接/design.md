# 第二十八垂直切片：城墙与城门连接结构设计

## 决策

城墙作为与道路平行的 1×1 权威坐标层 `walls`，不塞入普通建筑联合类型，也不消耗全局实体 ID。协议用 `build-wall-path` 原子提交正交连续墙段；当前 Web 仍逐格提交，为后续拖筑保留不破坏协议的扩展点。城门格不进入 `walls`，但渲染拼接时作为固定虚拟墙邻居，使 `(0,14)` 与 `(0,16)` 的墙段分别接入城门两端。

## 数据流

```text
建造栏“城墙” / 键盘确认
          ↓
evaluateWallPlacement（预览）
          ↓
build-wall-path [{x,y}]
          ↓
Worker / simulation 原子校验
  ├─ 越界、跳格、重复 → invalid/out-of-bounds
  ├─ 墙、路、建筑、城门冲突 → occupied
  └─ 全段合法 → walls + revision
          ↓
WorldSnapshot v7 → 自动保存
          ↓
wallConnectionMasks（含虚拟城门格）
          ↓
相机朝向换算 → 4×4 手绘墙体图集帧 → Babylon billboard
```

## 模块边界

### `packages/protocol`

- `SAVE_FORMAT_VERSION` 升为 7；冻结 `LegacyWorldSnapshotV6` / `SaveEnvelopeV6`，当前 `WorldSnapshot` 新增 `walls`。
- 新增 `BuildWallPathCommand`：1～1024 个安全整数坐标；结构协议只管形状，越界与路径连续性仍由 simulation 给出领域拒绝。
- v7 快照强校验墙坐标不重复、不占城门、不压道路或建筑；道路也不得压墙。
- v1～v5 先沿既有链迁到 v6，再由 `migrateV6WorldToV7` 补 `walls: []`；v6 的其他字段深拷贝保留。

### `packages/simulation`

- `WorldState`、创建、hydrate、clone、commit、snapshot 全链路携带排序后的 `walls`。
- `evaluateWallPlacement` 负责单格 UI 预览；建筑、道路放置同步把墙视为占用。
- `applyWallPathCommand` 先完整校验再一次提交：路径正交、无重复、无冲突、revision 可递增；只增加一次 revision。
- 通用拆除优先保持既有道路/建筑语义，再识别墙格；拆墙只移除目标坐标。
- 道路服务、物流、通勤、迁入和守军函数不读取 `walls`，以回归测试守住本轮玩法边界。

### `packages/renderer`

- 新建 `wall-autotile.ts`，复用北/东/南/西四位掩码语义；计算时把 `CITY_GATE_TILE` 加入占用集合，但只为真实墙格产出结果。
- 新建相机换算纯函数：把世界连接掩码按 0/90/180/270 度转为屏幕图集掩码；相机转动只换材质帧，不改权威世界。
- 一张 `4 行 × 4 列` 墙体图集按 mask `0...15` 排列，固定 cell 尺寸、bottom-center 脚点与透明 padding；复用 sprite-sheet UV 材质缓存。
- `wallMeshes` 以地格 key 稳定复用。增建/拆除时只创建、删除或换帧，不重建城门和其他对象。
- 墙体 billboard 使用独立相机更新，不套用普通建筑的水平镜像；四向方向完全由 presentation mask 决定。

### `apps/game-web`

- `BuildTool` 增加 `wall`；“城务”分类加入城墙卡片，沿用现有卡片尺寸、焦点、快捷键和禁用态。
- 预览、建造命令、成功/保存失败/拆除反馈补齐“城墙”；城墙仍是 1×1 绿色/红色放置预览。
- 概览统计增加城墙格数即可，不新增专属 HUD、弹窗或资源成本。

### `packages/persistence`

- 不新增存储表；继续保存完整 v7 envelope。
- 集成测试覆盖 v6→v7 原位升级和 v7 墙体刷新恢复。

## 视觉设计计划

**主题**：新国风手绘微缩古城的灰砖防线。玩家的注意力不在新按钮，而在城门两侧第一次延展开的连续垛口轮廓。

**材质色板**：城门灰砖 `#77756E`、夯土阴影 `#4B463E`、瓦顶炭灰 `#34383A`、旧石高光 `#AAA398`、苔痕橄榄 `#5C6848`；UI 不新增主题色，继续使用既有建造卡片系统。

**字体与布局**：完全沿用现有城司标题、正文和数据字体；“城墙”卡片进入城务分类，避免为了单一设施破坏既有信息架构。

```text
右侧营造指挥栏
┌────────────────────┐
│ 民生  产业  [城务] │
├─────────┬──────────┤
│ 税务署   │ 音乐学校  │
│ 步兵营   │ 贸易站    │
│ [城墙]   │ 拆除      │
└─────────┴──────────┘

地图西边界
      墙 (0,14)
          │
      ╔══城门══╗  ← 道路穿过 (0,15)
          │
      墙 (0,16)
```

**唯一视觉记忆点**：城门短墙垛与玩家墙体形成不中断的连续顶线。按钮只负责入口，地图轮廓负责表达能力。

**方案自审**：基础盒体虽然实现快，但违反项目真实运行素材纪律；为每段墙创建普通建筑会污染 ID 和连续设施语义。最终采用独立墙层 + 单张拼接图集，既保留手绘质感，也让连接方向和存档状态可测试。

## ATDD → TDD 拆解

1. **协议红绿**：`build-wall-path` 解析、非法结构拒绝；v7 墙快照与 v6 无损升级；墙/路/建筑/城门互斥。
2. **模拟红绿**：合法单格/多格墙路径；越界、跳格、重复和占用原子拒绝；双向放置冲突；拆墙与 revision 上限。
3. **Worker / 持久化红绿**：命令响应携带 walls；v7 保存恢复；v6 原位升级。
4. **拼接红绿**：16 种邻接掩码、虚拟城门连接、相机四分之一转掩码换算。
5. **素材红绿**：图集清单、4×4 帧映射、版本化文件存在且可解码；先用缺失资产让测试见红，再接入最终素材。
6. **Web 红绿**：城务分类卡片、预览、命令、成功/失败/拆除反馈、键盘路径。
7. **ATDD 外层**：Chromium 修墙、接门、非法冲突、拆墙、刷新恢复和四向相机；再跑既有人口/物流/守军回归。

## 兼容与故障处理

- v6 必须先按冻结 schema 解析，不能让新增可选字段偷改旧版本含义；迁移后统一产出 v7。
- 墙体图集加载失败时沿用当前 renderer 错误日志和可交互世界，不影响 Worker 权威状态；调试放置代理可见但不作为最终正常素材。
- 用户当前工作区有大量未提交修改，所有补丁以现有文件为基线做局部编辑，不回滚、不格式化无关文件。
