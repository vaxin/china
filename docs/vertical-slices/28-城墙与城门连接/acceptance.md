## 目标与范围

玩家可以从建造栏选择“城墙”，在空地上逐格修筑、拆除城墙；正交相邻的墙段自动连成连续墙体。地图西侧既有城门仍以 `(0,15)` 为道路入口，位于 `(0,14)` 与 `(0,16)` 的墙段分别接入城门两端，城门中央继续允许道路和人物通行。城墙进入权威快照与存档，刷新后完整恢复。

本轮完成“可建、可连、可拆、可保存”的防线施工基础。敌军、攻城单位、破墙耐久、箭塔、资源消耗和封闭防线判定留给后续战斗切片，不在本轮虚构未存在的入侵系统。

## 已识别现状

1. 城门是固定的非实体视觉对象，逻辑入口只有 `CITY_GATE_TILE = (0,15)`，且素材在世界 X 负方向偏移半格。
2. 道路、建筑和拆除都由 Worker 内权威世界决定；Web 仅发送命令和显示放置预览。
3. 道路已有四邻接自动拼接、占地互斥、原子拒绝和拆除回退，可作为城墙路径设施的行为基线。
4. 当前 `WorldSnapshot` 只有 `buildings` 与 `roads`，存档版本为 v6；城墙需要独立权威集合与兼容升级。
5. 运行画面要求使用版本化手绘透明素材；可见城墙不能退回 Babylon 基础盒体或占位色块。

## 产品与技术口径

1. **逐格营造**：[假设] 城墙是 1×1 路径设施，交互沿用道路——鼠标点击或键盘回车/空格一次修筑一格；底层命令支持连续正交墙段的原子提交，为后续拖筑保留接口。
2. **空间互斥**：墙段不能越界、压住建筑、道路、已有墙段或城门入口；新增道路和建筑也不能反向覆盖墙段。
3. **城门接点**：西侧城门的两个合法接点固定为 `(0,14)` 与 `(0,16)`；墙段在这些位置时须把城门视为虚拟相邻墙体，端头视觉贴合城门两侧，不在 `(0,15)` 封死门洞。
4. **自动拼接**：墙段按北、东、南、西四邻接稳定生成孤立、端头、直线、拐角、T 形和十字形；增建或拆除相邻墙段后，受影响墙段在同一快照中更新外观。
5. **真实素材**：城墙沿用当前古代中国手绘写实、灰砖夯土与深灰瓦色系；所有运行变体来自版本化透明素材，四向相机下与地格、城门落脚一致。
6. **拆除**：通用拆除工具可拆单格城墙；城门本体仍不可拆。拆除墙段只影响墙体，不误删相邻道路、建筑或城门。
7. **存档兼容**：新增 v7 存档；v1～v6 读取后补空城墙集合并可原位升级，既有建筑、道路、住户、人物、经济、tick、revision 与 ID 不变。
8. **玩法边界**：[假设] 本轮城墙不参与居民迁入、物流、通勤或守军部署判定；道路仍是唯一通行网络。墙体阻挡敌军与攻城破坏在后续切片补齐。
9. **营造成本**：[假设] 沿用当前道路与建筑工具，不新增石料、工人或国库扣费；资源化营造需等对应资源系统成形后单独验收。

## 视觉方向

**主题**：城门不再是一座孤零零的入口建筑，而成为一条可延展城防轮廓的核心节点。

**视觉记忆点**：从城门灰砖墙垛向南北自然延伸的连续垛口线。玩家只看轮廓就能读出直线、转角和缺口；拼接不能依赖浮动连接图标或调试线。

**克制项**：不新增城墙专属 HUD、粒子、发光描边或假 3D 占位盒；颜色、透视、砖尺度、瓦顶和接地阴影服从既有城门素材与四向相机表现。
