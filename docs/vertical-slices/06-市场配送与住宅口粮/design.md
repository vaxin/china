# 第六垂直切片：结构设计

## 数据与版本

- 当前存档版本提升到 v5；冻结 v4 的四类建筑与无口粮字段住户 schema。
- `BuildingView` 增加 `market(2×2, foodStock 0..4)`。
- `HouseholdView` 增加 `foodReserveTicks: 0|1|2|3`；字段表示可继续满足住宅粮食条件的 tick 数，不表示建筑库存单位。
- v4→v5 只为既有住户补 `foodReserveTicks: 3`，不创建市场、不增加建筑库存、不分配 ID、不增加 revision。
- 市场库存与住户口粮属于权威存档状态；道路距离和候选配送是 tick 内派生数据。

## Tick 相位

1. 校验 tick/revision 安全整数容量并令 tick +1。
2. tick 为 3 的倍数时，未满农场各产 1。
3. 按既有规则从农场向粮仓运输。
4. 按市场 ID 补货；每市场最多取 1，来源按道路距离、粮仓 ID。
5. 本 tick 开始时已存在的住户口粮大于 0 时减 1。
6. 按市场 ID 配送；每市场最多送 1 户，只选口粮为 0 的既有住户，目标按道路距离、住宅 ID。
7. 协调住宅：无城门道路则迁出；新住户以 5 人和 3 tick 随身口粮迁入；既有住户同时有水和口粮才为二级 10 人。
8. 任一库存、住户口粮、住户或住宅等级变化时，本 tick 的 revision 只增加 1。

临近安全整数上限时，沿用克隆世界预演和整批原子提交；口粮每次倒计时都属于物质状态变化，必须计入实际 revision 需求。

## 道路物流

- 把现有农场到粮仓 BFS 泛化为任意两建筑间的最短正交道路距离，并显式传入范围。
- 两建筑四边相邻道路格若相同，距离为 0；所有坐标先判地图边界再生成 tile key。
- 农场→粮仓和粮仓→市场范围为 12；市场→住宅范围为 8。
- 物流不要求连接城门；住宅人口存在性仍由独立的城门连通域约束。
- 市场顺序和候选排序只依赖稳定 ID 与距离；数组顺序不参与规则。

## 不变量

1. 五类建筑 ID 全局唯一，占地不重叠、不压道路和城门。
2. 市场库存是 0～4 的整数；拆市场删除其库存，但不回收或删除已送达住户的口粮。
3. 二级住宅必须有 10 人住户、有效水服务且 `foodReserveTicks > 0`；一级住户为 5 人并允许口粮 0～3。
4. 住户口粮可以在市场断路或拆除后继续存在，因此当前市场可达性不是存档强不变量。
5. 每市场每 tick 最多进 1、出 1；同一住户每 tick 最多收 1，库存永不为负或超过容量。
6. 快照按建筑 ID、道路 key、住户 houseId 稳定排序；表现层只读取结果，不参与权威计算。

## 前端设计计划

- **主题**：面向城市沙盘玩家的“古城营造司 · 民生簿”；页面唯一任务是让玩家在 3D 场景中建成并诊断供粮闭环。
- **色板**：夜墨 `#071214`、竹青 `#163032`、田青 `#667f58`、宣纸 `#eee2bf`、铜金 `#b89a55`、市幡朱 `#ad4b32`。
- **字体**：城名与建筑字牌使用 Songti SC/STSong；正文使用 Noto Sans SC/PingFang SC；数值和 tick 使用等宽字体。
- **布局**：保留全屏沙盘，HUD 扩为桌面 6×2、移动端 3×4；七个工具保持两列，拆除独占末行；供粮状态独立放入底部状态条。
- **视觉签名**：市场是低矮开放棚市——四根深木柱、两条朱红平行棚顶，中缝露出铜金货案；远景轮廓区别于扁平农场和高耸粮仓。
- **反模板复核**：不新增通用卡片、霓虹渐变或悬浮图表；朱红只用于市场棚顶、市场工具和缺粮警示。将“技术切片”改为“民生簿”，让结构与文案来自古城营造语境。
