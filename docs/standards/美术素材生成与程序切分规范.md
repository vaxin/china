# 美术素材生成与程序切分规范

> 适用项目：河洛原 3D 网页城市沙盘  
> 目标：让 Image Gen、手绘设定、2D 特效、纹理和 3D 模型进入同一条可重复、可验证、可替换的资产流水线。  
> 原则：生成图是源素材或设计参考；运行时资产必须经过确定性切分、命名、打包和校验。

## 1. 核心结论

1. **不要让 Image Gen 直接生成生产用大图集。** 生成模型难以长期保证每格尺寸、边界、视角、比例和锚点完全一致。
2. **一张生产源图只放一个对象或一个动画关键帧。** 先独立生成和清底，再由程序统一尺寸、锚点、padding，并打包成 atlas + JSON。
3. **人看的设定稿与程序吃的素材分开。** 多对象场景稿、四视图和施工阶段对照表用于评审；它们不直接进入游戏。
4. **Image Gen 不产生最终 3D 几何。** 建筑和人物最终使用 glTF/GLB；生成图主要提供造型、材质、配色和动作参考，也可作为纹理源图。
5. **先锁一个视觉锚点，再做变体。** 先确认一张风格场景稿和一张角色母稿，后续编辑每次只改变一个变量，并重复写明必须保持不变的部分。

## 2. 两类输出必须分开

### 2.1 设计评审稿

允许一张图包含多个对象，用于确定风格和比例：

- 城门、道路、宅基地、施工住宅、建成住宅和流民同框的风格场景稿。
- 宅基地 → 地基 → 木架 → 封顶 → 建成的施工阶段设定稿。
- 流民正面、侧面、背面和 3/4 视图的角色设定稿。
- 等待、行走、搬运、施工的动作关键姿势表。
- 瓦、木、灰墙、夯土、布幡的材质与色板。

这些图片只作为设计输入，不能被运行时代码直接切片引用。

### 2.2 生产源素材

每个文件只包含一个明确对象：

- 单栋建筑或单个施工阶段。
- 单个角色参考视图或动作关键帧。
- 单个尘土、碎屑、落叶等 2D 特效。
- 单种可平铺材质。

生产源素材经过清底和 QA 后，才能进入 atlas、GLB 或材质制作流程。

## 3. Image Gen 工作流

### 3.1 风格锁定

1. 先生成一张完整场景稿，确定时代气质、相机、光线、色板和轮廓语言。
2. 选中的场景稿成为 `style-anchor`，后续所有建筑和人物生成都把它作为风格参考。
3. 再生成角色母稿 `villager-anchor`，冻结脸型、身体比例、服装、配色和随身物件。
4. 每轮只调整一个变量，例如只改姿势、只改施工阶段或只改屋顶等级。

### 3.2 可清底源图

Codex 内置 Image Gen 默认不依赖原生透明参数。简单不透明对象使用纯色键控背景生成，再本地去底：

- 默认键色：`#00ff00`。
- 对象包含大量绿色时改用：`#ff00ff`。
- 背景必须完全纯色，不得有阴影、渐变、纹理、地面、反射或光照变化。
- 对象必须完整，边缘清晰，四周保留至少约 12% 安全边距。
- 键色不能出现在对象本身。
- 禁止投影、接触阴影、文字、水印和无关道具。

本地清底命令：

```bash
python3 "${CODEX_HOME:-$HOME/.codex}/skills/.system/imagegen/scripts/remove_chroma_key.py" \
  --input <source.png> \
  --out <output.png> \
  --auto-key border \
  --soft-matte \
  --transparent-threshold 12 \
  --opaque-threshold 220 \
  --despill
```

若头发、烟雾、玻璃、液体、半透明布料或软阴影导致键控去底失败，不应强行扩大容差；应改用可提供原生透明的受控生成流程，并重新验证边缘。

### 3.3 通用生产提示词模板

```text
Use case: stylized-concept
Asset type: game production source / <具体资产>
Primary request: <一个对象或一个动作>
Input images: Image 1 is the style anchor; Image 2 is the character/building anchor
Subject: <主体、服装、结构和功能道具>
Style/medium: stylized historical Chinese miniature, hand-painted material language
Composition/framing: fixed 45-degree orthographic three-quarter view; complete object; centered
Lighting/mood: neutral soft studio light matching the style anchor
Color palette: preserve the anchor palette
Scene/backdrop: perfectly flat solid #00ff00 chroma-key background
Constraints: preserve proportions, camera, light direction and material language; one object only; generous padding; no crop; no text; no watermark; no cast shadow; no reflection
Avoid: extra props, scenery, labels, borders, dramatic perspective, photorealism, toy-plastic look
```

### 3.4 角色动作变体模板

```text
Use case: identity-preserve
Asset type: game character animation reference
Input images: Image 1 is the approved villager anchor
Primary request: change only the pose to <idle / walk contact / walk passing / carry / build strike>
Subject: the exact same villager, face, body proportions, clothing, colors and accessories
Composition/framing: full body visible; feet on the same baseline; same camera and scale
Scene/backdrop: perfectly flat solid #00ff00 chroma-key background
Constraints: change only the pose; preserve identity and outfit; hands and feet fully visible; no text; no shadow; no extra object unless the action requires the approved tool
```

### 3.5 无缝材质模板

```text
Use case: stylized-concept
Asset type: tileable game texture source
Primary request: seamless <gray plaster / dark timber / baked clay roof tile / rammed earth> texture
Style/medium: hand-painted stylized realism matching the approved city style anchor
Composition/framing: flat orthographic material swatch; uniform texel distribution
Lighting/mood: neutral diffuse lighting; no directional cast shadow
Constraints: seamless edges; no focal object; no perspective; no text; no logo; restrained variation
```

生成结果仍需用偏移检查、接缝修复和缩小预览验证，不能仅凭提示词宣称“无缝”。

## 4. 项目坐标、比例与锚点

### 4.1 世界约定

- 规则层平面坐标：`X/Z`；高度：`Y`。
- `1 tile = 4m × 4m`。
- 普通住宅、农场、粮仓和市场占 `2×2 tile = 8m × 8m`。
- 建筑模型根节点位于占地中心，地基面为 `Y=0`。
- 建筑 `rotation=0` 的正面方向在批量建模前用首个住宅 GLB 做一次 Babylon 实机确认，此后不得单资产自行改变。
- 人物根节点位于双脚中点，站立地面为 `Y=0`。

### 4.2 2D 锚点

- 人物 billboard 或动作帧：`bottom-center`，所有帧共用脚底基线。

### 4.4 四方向人物步行 Sprite Sheet

- 每个职业交付一张 sheet，不输出散帧作为运行时资产。
- 固定布局为 **4 行 × 8 列**：行依次为 `south-east / south-west / north-west / north-east`，列 `0...7` 构成一次首尾连续的完整步态。
- 每格尺寸、人物缩放、脚底基线、bottom-center pivot 与透明 padding 必须完全一致；人物、工具和衣摆不得越格。
- 四个方向都须独立绘制身体透视和工具遮挡；禁止用左右镜像伪造前后方向。左右方向仅在人物服装和工具完全对称且美术验收明确允许时复用。
- 八帧至少覆盖：左脚接地、右腿通过、右脚前伸、右脚接地、左腿通过、左脚前伸，以及两个承上启下的重心转换帧；相邻帧轮廓必须在实际游戏显示尺寸下可辨。
- 源 sheet 使用无格线纯色键色背景或透明背景；运行时文件必须为带 alpha 的 PNG/WebP，并配套 JSON 记录 `rows=4`、`columns=8`、方向行序、cell 尺寸、pivot 与帧时长。
- 自动 QA：尺寸可整除、透明四角、32 格全部有人物覆盖、脚底基线误差不超过 2 px、人物包围盒高度漂移不超过 3%、相邻帧非零差异达到阈值。
- 居中特效：`center`。
- 落地尘土、脚印等：`bottom-center`。
- 同一动画的所有帧必须使用相同画布尺寸，不得逐帧自动紧裁后直接播放。

## 5. 图集与程序切分规范

### 5.1 规则图集

相同尺寸的动画帧使用统一 cell：

- 每格宽高固定。
- 帧按播放顺序排列。
- 所有帧锚点一致。
- 不允许打包器旋转动画帧。
- Babylon `SpriteManager` 通过 `cellWidth/cellHeight` 或统一 `cellSize` 读取。

### 5.2 Packed 图集

不同尺寸的图标、特效和装饰素材使用 packed atlas：

- atlas 图片与 JSON 同名并同目录。
- JSON 记录每个素材的 `x/y/w/h`、pivot 和原始尺寸。
- Babylon 使用 `SpritePackedManager` 或项目自有 manifest 读取。
- 打包必须由脚本完成，不手工记录坐标。

### 5.3 项目默认参数

- 素材间透明 padding：**至少 4 px**；启用 mipmap 或缩放明显时优先 8 px。
- 可见边缘向 padding 扩展 1～2 px，避免透明边缘采样出黑边或串色。
- UI 和动画图集禁用旋转打包。
- 不强制所有图集为 2 的幂，但单张 atlas 默认不超过 `2048×2048`；超过时按用途拆分。
- alpha 素材使用 PNG 或支持 alpha 的 WebP；不得把有透明边缘的素材转成 JPEG。
- 每张 atlas 必须在 100%、50%、25% 缩放下检查串色和边缘光晕。

示例 manifest：

```json
{
  "image": "villager-effects.png",
  "frames": {
    "dust_puff_01": {
      "x": 8,
      "y": 8,
      "w": 128,
      "h": 128,
      "pivot": [0.5, 0.85],
      "sourceSize": [128, 128]
    }
  }
}
```

## 6. GLB 建筑与人物规范

### 6.1 通用

- 运行时格式：`.glb`。
- 单位：米；导出前应用 transform 和 modifier。
- 不导出相机、灯光、隐藏草稿物体或无用骨骼。
- mesh 使用三角面；避免松散点、松散边和无材质面。
- UV 不重叠区域保持一致 texel density，并留足 island 间距，避免 mipmap 渗色。
- 重复瓦片、梁柱、树木和道具优先共享 mesh/material 或实例化。
- 资产提交前通过 Khronos glTF Validator；上线前再评估 MeshOpt/Draco 与 KTX2 压缩。

### 6.2 建筑

- 根节点：占地中心 `Y=0`。
- 首个 MVP 模型：城门、道路、宅基地四阶段、一级住宅、二级住宅。
- 同类阶段共享材质和比例，不通过整体缩放伪造升级。
- 屋檐、入口和功能性道具允许适度夸张，以保证当前正交远景下可读。

### 6.3 人物

- 第一版只做一种流民/建造者，不制作通用市民系统。
- 必需动画组名称：

```text
idle
walk
build
carry
```

- 动画应原地播放；世界位移由模拟和渲染插值控制，避免 root motion 与道路坐标冲突。
- 双脚接触地面时不能滑步；工具握持点和锤击点需要固定 socket 或明确骨骼。
- 人物在 Babylon 导入后必须能从 `animationGroups` 按名称取得动画。

## 7. 文件结构与命名

建议目录：

```text
assets/
  source/
    concepts/
    anchors/
    cutouts/
    textures/
  runtime/
    models/
    textures/
    atlases/
    manifests/
  licenses/
```

命名规则：

- 仅使用小写英文字母、数字、下划线和短横线。
- 名称表达类别、对象、等级或阶段，不依赖目录顺序。
- 禁止 `final-final2.png`、`新建文件.png` 等不可追踪名称。

示例：

```text
style_anchor_city_v01.png
villager_anchor_v01.png
residential_plot_stage_0.glb
residential_plot_stage_1.glb
residential_plot_stage_2.glb
house_level_1.glb
house_level_2.glb
villager_builder.glb
villager_effects.png
villager_effects.json
```

## 8. 资产台账

每个进入仓库的资产必须记录：

- 资产 ID 与文件路径。
- 用途和当前状态：草稿、已选、生产中、已验收、废弃。
- 来源：Image Gen、原创建模、购买、开源或外包。
- 作者或生成工具。
- 许可证与商用权限。
- 原始提示词、参考图和后处理步骤。
- 导出工具版本。
- 评审截图与替代资产关系。

原作《皇帝：龙之崛起》的截图只能作为玩法与时代氛围研究输入，不能提取、描摹或复用其模型、贴图、UI、音频和逐字数据。

## 9. 自动验收清单

### Image Gen 源图

- [ ] 一图一对象/一关键帧。
- [ ] 与 style anchor 的相机、比例、光向和材质语言一致。
- [ ] 主体完整，无裁边、重复肢体和多余道具。
- [ ] 无文字、水印、边框和场景背景。
- [ ] 清底后四角透明，边缘无键色残留和明显白/黑边。
- [ ] 原提示词、参考图角色和后处理记录已入台账。

### 图集

- [ ] atlas 与 JSON 同名且可解析。
- [ ] 帧坐标没有越界或重叠。
- [ ] pivot 与 sourceSize 存在且符合资产类别。
- [ ] padding ≥4 px；动画帧未旋转。
- [ ] 100%、50%、25% 下无串色、接缝和边缘光晕。
- [ ] Babylon 实机播放顺序和循环区间正确。

### GLB

- [ ] 单位、朝向、占地和根节点正确。
- [ ] 地基/脚底为 `Y=0`。
- [ ] glTF Validator 无错误。
- [ ] 无多余相机、灯光、隐藏对象、材质和动画。
- [ ] 材质、贴图和 mesh 命名稳定。
- [ ] 人物包含并可播放 `idle/walk/build/carry`。
- [ ] 当前正交相机下轮廓、入口和功能仍清晰。
- [ ] Chrome、Firefox、Safari/WebKit 均可载入，无控制台错误。

## 10. 第一批素材包

只制作高保真表现闭环，不扩玩法：

1. `style_anchor_city_v01.png`：城门、道路、宅基地、施工、住宅、流民同框。
2. `residential_construction_reference_v01.png`：宅基地到建成的阶段设定。
3. `villager_anchor_v01.png`：流民四视图与基础配色。
4. `villager_action_reference_v01.png`：等待、行走、搬运、施工关键姿势。
5. 城门、道路、宅基地三阶段、一级住宅、二级住宅 GLB。
6. 流民 GLB 与 `idle/walk/build/carry` 动画。
7. 尘土与碎屑 2D atlas。

第一批通过后，再沿同一规范替换水井、农场、粮仓和市场，不增加新的模拟功能。
