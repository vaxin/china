## 已决议的产品口径

1. **运转周期**：沿用现有模型，1 tick 为一个月度结算期，12 tick 为一年。
2. **过渡经济主体**：本里程碑中，国库暂时代表公共雇主和公共市场结算方。企业里程碑再将它们拆成独立账户。
3. **货币**：只使用非负安全整数“钱”，不引入小数与多币种。
4. **家庭启动金**：新迁入家庭携带 12 钱城外资产；这是明确记录的外部货币流入，旧存档迁移使用同一默认值。
5. **劳动分配**：现有劳动报告给出的已分配工人数，按稳定家庭 ID 顺序分配至各户的可用劳动人口；各户有明确的就业人数和月工资。
6. **工资**：沿用低/标准/高薪 1/2/3 钱/人/月；工资从国库转入家庭，国库不足时按家庭 ID 稳定顺序支付，未付部分记为欠薪而不透支。
7. **税收**：税务系统计算应纳额，但国库只收到家庭实际支付的数额；不足部分记税欠，家庭余额不得为负。
8. **口粮价格**：本里程碑固定为 1 钱/份；一份交付后补至现有的 3 tick 家庭口粮上限。
9. **下单时机**：口粮剩余 1 tick 时自动尝试下单；同一家庭最多一笔在途订单，防止重复扣款。
10. **支付与配送**：下单时预扣家庭 1 钱并预留一份市场库存；配送至少跨越一个 tick，交付时才增加家庭口粮。
11. **配送失败**：交付前断路或目标失效，订单取消，全额退款并释放预留库存。
12. **缺粮归因**：口粮归零时，必须区分“配送在途、无路可达、市场缺货、家庭无钱、附近无市场”；不能只显示统一的“缺粮”。
13. **存储上限**：每户最多保留 12 条最新生计流水，不无限放大存档。

## 可视化方向（验收级）

**主题与单一任务**：古代中国城市管理者查阅一户人家的生计；页面的单一任务是在十秒内回答“这户人现在靠什么生活，卡在哪里”。

**视觉语言**：沿用项目现有深色漆木/羊皮纸 HUD，但不做通用数据看板。唯一视觉记忆点是一条像城中水道一样连接四个站点的“生计流”；站点不是装饰编号，而是真实因果顺序。

```text
┌ 住户 #12 · 尚可度日 ─────────────────────┐
│                                                │
│  劳作  ─────  钱袋  ─────  采办  ─────  粮瓮      │
│  2 人       17 钱       运粮中       剩 1 月     │
│                         ↑ 当前环节             │
│                                                │
│  本月：工资 +4  税款 -2  口粮 -1          │
│  近 12 笔流水 …                            │
└────────────────────────────────────────────────┘
```

**色彩与字体令牌**：实作前从现有 CSS 变量提取，不平行发明新品牌。功能色限制为木金黄（正常流动）、青瓷蓝绿（在途）、石榴暗红（阻塞）、烟墨灰（未激活）；所有状态同时有文字/图形编码。

**动效**：只在“当月有一笔生计事件正沿链路发生”时，让链上一枚小光点单向流动；其他动效删除。减少动效模式下用静态箭头代替。
