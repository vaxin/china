# 粮食经济合理化改造验收

**执行记录**：[execution-log.md](./execution-log.md)

## 本轮范围与假设

本轮将现有的“农场 → 粮仓 → 市场 → 家庭”库存链改成受真实劳动力、人口需求和经营账户约束的食品经济链。

- [假设 F-01] 一单位粮食供 **5 人一月**；家庭月需求为 `ceil(residents / 5)`。家庭最多储备三个月的实际粮食单位，界面继续显示可维持的月数。
- [假设 F-02] 农场收获、农场到粮仓、粮仓到市场均须由对应岗位实际配足才发生；未配足时库存不变并在建筑详情中可见“缺工”。
- [假设 F-03] 市场向家庭售粮的固定价格仍为每单位 1 钱。售粮款进入市场账户；市场补货时等额支付粮仓，粮仓收粮时等额支付农场。国库不再直接获得售粮款。
- [假设 F-04] 每个经营性建筑有独立余额；其雇工工资从所属建筑余额支付，余额不足会产生可观察的欠薪并使该建筑下月停止需要付费的生产/物流活动。
- [假设 F-05] 删除无条件、无限距离的自动粮仓救济。家庭只能经可达市场获得粮；缺粮原因保持可解释。
- [假设 F-06] 食物品质仍按市场的作物多样性计算，本轮不额外改变健康、迁徙或价格；保质、灾害、播种投入、动态价格不在本轮范围。
- [假设 F-07] 满编农田在其收获月基础产出 **12 份**粮食；神农信仰达到既有加成门槛时额外产出 6 份。农田库存上限调整为 18 份，粮仓上限调整为 36 份，避免收获立即被旧容量截断。按 F-01，一座普通农田的年产量恰好覆盖一个 5 人家庭全年所需；10 人家庭需要两座普通农田或对应的增产来源。

## 结构设计

- 协议升级为 v9：家庭以 `foodReserveUnits` 保存真实库存；`foodReserveTicks` 由单位库存和家庭月需求推导并保留为兼容展示字段。旧档按 `foodReserveTicks × ceil(residents / 5)` 迁移。
- 农场、粮仓与市场新增 `operatingCash`、`wageArrears` 与 `staffedWorkers`。余额随货物流转；岗位分配按稳定建筑 ID 逐座落位。
- 每 tick 的顺序为：岗位落位与欠薪状态 → 农业生产/转运 → 家庭耗粮 → 已付款订单交付或退款 → 建造与人口协调 → 建筑付薪、家庭工资与税收 → 新订单。经营建筑只有满足岗位和本月工资支付能力时才运作。
- 市场订单以实际粮食单位为数量；市场按订单数量预留库存、按距离交付；家庭付款只进入市场。市场补货付款进入粮仓，粮仓收粮付款进入农场。
- 删除自动粮仓救济。任何断粮必须由市场可达性、库存、现金或在途订单解释。
